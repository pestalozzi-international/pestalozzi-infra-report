01 — Current Situation

How Our Website Works Today

Our website pestalozzi.international is made up of two connected parts: what visitors see (the "frontend") and the system our team uses to write and publish content (the "backend" or CMS). These two parts are currently managed separately — and almost entirely by our external agency, Lucid.

The Key Point

Almost every part of our website infrastructure is owned, controlled, or managed by Lucid. We are a tenant in their system — not an owner of ours. This has significant practical and financial consequences.

What we currently own outright

The domain name pestalozzi.international, our DNS settings (managed via Cloudflare), our Plausible analytics account, and our Hostinger server panel access. Everything else sits inside Lucid's accounts and infrastructure.

02 — The Problems

Why the Current Setup
Doesn't Work For Us

The arrangement made sense when Lucid built the website. But as an ongoing operational reality, it creates a set of problems that affect our team every day and cost us money we shouldn't be spending.

1

We pay to make simple changes

Adding a Google Analytics tag, updating a script, or changing a tracking pixel requires a Lucid developer at CHF 190/hour. These are 5-minute tasks that we cannot do ourselves because we don't have access to the code.

2

We don't own our own code

The source code of our website lives in Lucid's GitHub account. If our relationship with Lucid ends abruptly, accessing or continuing the website becomes complicated.

3

We have unused Azure credits going to waste

As an NPO, Microsoft grants us $2,000 in Azure cloud credits per year. We are currently not using any of them, while paying Hostinger (~CHF 150/year) for the same type of service.

4

Bot traffic is costing us money

Our analytics show that ~49% of website "visitors" are actually automated bots, primarily from China. This inflated traffic has pushed us beyond the standard limits on Netlify, creating potential for unexpected extra charges.

5

We pay annual software licenses we could avoid

We pay CHF 172/year for Craft CMS and plugins, and CHF 46.47/year for font licenses. Free, equally capable alternatives exist for both.

6

No signed agreement for key services

The Frontend Hosting Agreement (the contract for our Netlify hosting) was drafted in February 2025 but has never been signed. The contact person on Pestalozzi's side is listed as "TBA." We are paying for a service with no formal contract in place.

03 — The Proposed Solution

Taking Ownership of
Our Own Infrastructure

The proposal is straightforward: move our entire website infrastructure onto Microsoft Azure — cloud services that Pestalozzi International already has $2,000/year in free credits to use, as an NPO. This means we host everything ourselves, own everything ourselves, and stop paying intermediaries.

What Azure Is

Microsoft Azure is the same cloud platform used by thousands of NGOs, universities, and corporations worldwide. As a registered non-profit, we receive $2,000 in free credits every year through Microsoft's NPO programme — more than enough to run our entire website at zero cost.

What changes for our content team?

Very little day-to-day. The CMS editing interface will look and feel similar. Content editors will still log in to a web-based interface to write news articles, update programme pages, and upload media. The key difference is that the system will be ours — no license fees, no dependency on any agency.

What changes for IT?

Everything positive. Any technical change — adding Google Analytics, updating scripts, changing fonts, adding a page template — can be done directly by Thomas without involving or paying an external developer. We will have full SSH and admin access to every layer of the system.

04 — Migration Plan

How We Get From Here
to There

The migration is structured in six phases. Thomas will handle the majority of the work directly — reducing the hours we need to pay for. The only external developer time required is for specialised technical configuration (approximately 4–7 hours).

Important First Step — Before Anything Else

We must formally request our assets from Lucid in writing: the website source code (GitHub access), the server configuration file (.env), all software license keys, and the deployment pipeline setup. This is our data and they are obligated to provide it. This request should come from leadership, not IT, to set the right tone.

Phase 0 — Week 1
Formal Asset Request to Lucid
Send a professional written request for all code, credentials, and license keys. Simultaneously, Thomas creates the Azure resource group and begins provisioning the three services (App Service, MySQL, Blob Storage).
Thomas handles Leadership signs off
Phase 1 — Week 2
Set Up Azure Infrastructure
Thomas creates all Azure services through the Azure portal — a guided process requiring no advanced technical knowledge. This is our "new home" being prepared before anything moves.
Thomas handles
Phase 2 — Week 2–3
Move the Data
Thomas exports the database from Hostinger (a few clicks in the admin panel) and downloads all website files. These are then uploaded to Azure. This is the "moving boxes" phase — no specialist needed.
Thomas handles
Phase 3 — Week 3
Technical Configuration
A freelance developer (4–7 hours, CHF 80–120/hour) configures the CMS to talk to the new Azure database, sets up file storage, and creates the automated deployment pipeline from GitHub. Thomas participates throughout to learn the system.
4–7h developer time Thomas co-pilots
Phase 4 — Week 3–4
Test Everything Thoroughly
The new site runs in parallel with the old one. Content team members test the CMS interface. We verify that all pages load correctly, forms work, documents download, and all languages display properly. No visitors are affected — they still see the old site.
Thomas + content team
Phase 5 — Week 4
Go Live
Thomas updates two DNS records in Cloudflare — a process taking under 5 minutes. Traffic switches to the new Azure infrastructure. The old Hostinger server remains on standby for 48 hours as a safety net, then is cancelled. We are free.
Thomas handles
Zero Downtime

The old website remains fully live throughout the entire migration. Visitors will not experience any interruption. The switchover itself takes seconds via a DNS update.

05 — Life After Migration

What Changes for
Pestalozzi International

🔑
Full Ownership
Every piece of our website — code, content, data, and infrastructure — is owned and controlled by Pestalozzi International. No agency holds keys to our house.
⚡
Instant Changes
Adding Google Analytics, updating a tracking pixel, changing fonts, adding a script — Thomas does this in minutes with no external invoice. We stop paying CHF 190/hour for 5-minute tasks.
🛡️
Bot Protection
Activating Cloudflare's free proxy (we're already on Cloudflare) will block the bot traffic that currently represents ~49% of our "visitors" and was threatening extra charges on Netlify.
💰
Significant Savings
Annual software costs drop dramatically. Our $2,000 Azure credits cover all hosting. The only remaining annual cost is the Craft CMS license — which can also be eliminated by switching to a free CMS.
📊
Real Analytics
With Google Analytics installed (free, 5 minutes) alongside Plausible, we get comprehensive data on our real audience — approximately 1,960 genuine human visitors per month, globally distributed across our programme countries.
🔒
GDPR Compliance
Self-hosting fonts eliminates third-party font requests. Choosing Sweden Central on Azure keeps all data within the EU. Cloudflare's proxy adds an additional layer of data protection.

What about the content team's day-to-day?

The content editing experience will be preserved. Editors will still log in to a web-based CMS to write and publish content. If we choose to migrate from Craft CMS to a free alternative (Directus, Payload, or Decap CMS), we will conduct a structured training session before the switch. The visual interface is comparable and in some cases more user-friendly than Craft.

What is the risk?

The main risk is timing — specifically, Lucid's speed in providing our assets. We have mitigated this by structuring the migration so that Thomas can proceed with Azure setup in parallel. The technical configuration phase (4–7 hours of developer time) is the only hard dependency. We recommend engaging an independent Craft/CMS developer through Malt or Upwork well in advance of needing them.
