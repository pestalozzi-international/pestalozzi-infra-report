Current Architecture

The website is a decoupled CMS architecture: a Craft CMS backend serving content via GraphQL, consumed by a Nuxt.js/Vue.js frontend. Currently split across Hostinger (backend) and Netlify (frontend), with GitHub and Buddy handling CI/CD. All infrastructure currently sits under the agency's accounts.

Full migration to Azure, with the frontend moving to Azure Static Web Apps (free tier) and the backend stack replacing Hostinger with three managed Azure services. CI/CD moves from Buddy to GitHub Actions. Thomas will handle Azure provisioning, database export, and file transfer. Developer scope is CMS reconfiguration, Blob adapter, and GitHub Actions workflow.

Developer Scope of Work

Thomas handles: Azure provisioning, database export and import, file transfer, DNS cutover on Cloudflare, and Azure Static Web Apps setup. The following tasks are the contracted developer scope:

TASK-01
Craft CMS — Environment Reconfiguration for Azure
~2h estimated

Update .env for Azure MySQL connection string. Verify config/db.php and config/general.php for environment-specific settings. Run php craft migrate/all and php craft project-config/apply post-deploy. Confirm Craft admin accessible at cms.pestalozzi.international.

bash — .env changes required
# Current (Hostinger) DB_DRIVER=mysql DB_SERVER=localhost DB_PORT=3306 DB_DATABASE=craft_prod DB_USER=[from_hostinger] DB_PASSWORD=[from_hostinger] # Target (Azure MySQL Flexible Server) DB_SERVER=[name].mysql.database.azure.com DB_PORT=3306 DB_DATABASE=craft_prod DB_USER=[azureuser]@[name] DB_PASSWORD=[azure_password] MYSQL_ATTR_SSL_CA=/etc/ssl/certs/DigiCertGlobalRootCA.crt.pem
TASK-02
Azure Blob Storage — Craft Flysystem Adapter
~2h estimated

Install and configure the Azure Blob Storage adapter for Craft's asset filesystems. App Service does not provide persistent local disk — uploads must be redirected to Blob. Use craftcms/flysystem-azure-blob-storage or equivalent. Update filesystem config in Craft admin and config/filesystems.php. Migrate existing web/uploads contents to Blob container.

bash — composer install
composer require craftcms/flysystem-azure-blob-storage
php — config/filesystems.php
return [ 'assets' => [ 'driver' => 'azure', 'account' => App::env('AZURE_BLOB_ACCOUNT'), 'key' => App::env('AZURE_BLOB_KEY'), 'container' => App::env('AZURE_BLOB_CONTAINER'), 'url' => App::env('AZURE_BLOB_URL'), ], ];
ℹ️
Asset URL update: After moving uploads to Blob, all existing GraphQL asset URLs will change from cms.pestalozzi.international/uploads/… to the Blob CDN URL. Verify the Nuxt frontend handles this correctly — check the GraphQL asset URL transform config.
TASK-03
GitHub Actions — CI/CD Pipeline (replaces Buddy)
~1.5h estimated

Create two GitHub Actions workflows: one for the Nuxt.js frontend (deploy to Azure Static Web Apps), one for the Craft CMS backend (SSH deploy to App Service, run migrations). Thomas will provide Buddy pipeline config as reference. Secrets to be added to GitHub repo settings by Thomas.

yaml — .github/workflows/deploy-backend.yml (skeleton)
name: Deploy Backend to Azure on: push: branches: [main] jobs: deploy: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - name: Backup DB before deploy run: # mysqldump via SSH to Azure MySQL - name: Deploy via SSH uses: appleboy/ssh-action@v1 with: host: ${{ secrets.AZURE_APP_HOST }} username: ${{ secrets.AZURE_SSH_USER }} key: ${{ secrets.AZURE_SSH_KEY }} script: | cd /home/site/wwwroot git pull origin main composer install --no-dev php craft migrate/all php craft project-config/apply
TASK-04
App Service Configuration & Queue Runner
~0.5h estimated

Configure PHP settings on App Service (memory_limit, upload_max_filesize, max_execution_time). Set up the Craft queue runner as a background process or WebJob. Confirm any cron jobs from Hostinger are replicated (e.g. php craft queue/run scheduling).

ini — php.ini overrides (App Service configuration panel)
memory_limit = 256M upload_max_filesize = 64M post_max_size = 64M max_execution_time = 120

✅
Sizing verdict: B1 App Service is appropriate for this traffic profile. A low-traffic CMS serving GraphQL to a static frontend will not stress B1. Monitor CPU/RAM for first 30 days; upgrade to B2 only if sustained >70% CPU is observed. Azure Static Web Apps free tier (100 GB/month) is vastly oversized for actual needs.
⚠️
Bot mitigation: Cloudflare proxy should be enabled on DNS records post-migration (Thomas handles this). This will eliminate bot traffic reaching the origin server. Consider adding a robots.txt update and Cloudflare bot challenge for high-frequency bot sources.
